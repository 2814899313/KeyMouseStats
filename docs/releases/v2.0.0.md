# KeyMouseStats 2.0.0

2.0 做了三件事:**新增第 7 页「字符内容」**、**新增第 8 页「日报」**,以及**把开机自启从注册表换成计划任务**。

字符内容页让键鼠统计第一次能回答「打出来的是什么」——数据来自输入法自己写的上屏日志,程序本身依旧不记录任何输入文字。

## 为什么单独做一页

键鼠数据回答的是「按了多少次」:击键、点击、路程、时长、应用归因。它从设计上就不看内容,所以「我这一天到底写了多少字」这个问题一直没有答案。

字符内容页补的就是这一半。但它和键鼠数据**性质不同**:按键次数是行为统计,上屏明文是内容。所以这一页从数据层开始就和键鼠分开:

- 只读一个文件,不挂钩子、不读剪贴板、不碰输入法进程;
- 字符数据不进 `stats.txt`,不参与导入合并、月度归档、多机合并,也不出现在键鼠的 CSV 导出里;
- 不与前台应用、窗口标题产生任何复合键——「哪个应用里输入了哪些字」这种视图,本版不做。

## 数据源

`%APPDATA%\Rime\commit_log.csv`,三列:`时间点,汉字个数,汉字明文`。一行是一次上屏。

只读文件尾部 8 MiB、内存里最多保留 20 万条,读盘按设置节流(见下一节)。这不是抠门:这个 UI 线程同时还在跑低级键鼠钩子,同步读一个几十 MB 的文件停顿超过 300 ms,系统就会静默摘钩子(见 `docs/` 里 1.8.0 的线程约束)。文件被截断、或者丢弃了更早的记录时,页脚会写清楚。

## 刷新频率可配置

页面右上角的 `刷新 N 秒 ▾` 有六档:**3 / 10 / 15 / 30 / 60 秒 / 手动**,默认 15 秒。选择即时生效、就地重读,不用重启面板。菜单第一项是**立即重新读取**,等不及兜底间隔时点它。

三种触发是分开的:

- **文件改动**永远优先。输入法一写新行,下一次重绘就重算,通常不到 1 秒。这条不受设置影响。
- **文件体积**变化也算改动。只比 mtime 会踩到文件系统的属性缓存(另一个进程刚写完、缓存里还是旧时间),所以 mtime 与字节数任一变化都会重读。
- **间隔只是兜底**。文件没变也每隔 N 秒强制重读一次。

「手动」等于关掉兜底:只有文件真的改动、或者点「重新读取」时才碰盘。

设置写进数据文件的可选行 `text_refresh_v1=<秒>`。旧版读到不认识的键会直接忽略,所以回退到 1.8.x 不会损坏数据;反过来,旧文件没有这一行时本版保持默认 15 秒。合法值被夹在 2 秒 ~ 1 小时,写坏的值不会让页面停止刷新。

## 页面内容

- **四张数字卡**:区间上屏字数、上屏次数、平均每次字数、今日字数;前两张下方标「较上期 ±%」。
- **每日上屏字数**:柱状图,今日主色高亮,没有记录的日子补零(趋势图不能有洞)。
- **按时段分布**:同一张卡片上切「每日 / 时段」。时段视图把区间内所有字数按 24 小时累加,回答的是「我一般几点写得多」——不随日期变化;最活跃的小时用主色标出。
- **词长 / 构成 / 节奏**:右卡三模式。词长是「一次上屏几个字」(输入法的词组粒度);构成把码点分成汉字、标点、字母数字、空白、其他五类;节奏给出平均每分钟字数、最快一分钟、有上屏的分钟数、最长连续输入段(间隔 >2 分钟断开)。
- **高频字符 Top 20**:4 列 × 5 行的排行榜(20 行竖排放不下这张卡的高度),名次 + 16 px 粗体字符 + 次数,前 3 名用主色;底部给出前 20 个占区间总字数的比例。
- **最近上屏**:最近 6 条「时间 + 明文 + 字数」,用来核对某天的数字到底来自哪些输入。
- **悬停读数**:柱子、排行行、最近记录都能悬停,浮层给出该元素的明细;`Ctrl+C` 复制的也是当前悬停项,没有悬停时回落到整页摘要。

区间四档 `今日 / 近 7 天 / 近 30 天 / 全部`,页脚 `导出 CSV` 导出当前区间的「时间、字符数、明文」。

## 口径

- **字符按 Unicode 码点计数**:代理对(扩展区汉字、emoji)算 1 个字。词长、字符频次、平均值共用同一套码点枚举,不会出现「总字数 5、词长却是 4」这种自相矛盾。
- **CSV 走完整引号解析**:上屏文本里出现英文逗号或双引号时,`Split(',')` 会把整行切错,这里按 RFC 4180 处理引号与 `""` 转义。另外两处会漏数据的口子也堵上了:明文带英文逗号而写入方没加引号时,后面的字段拼回明文;明文带换行时记录会跨行,一直拼到引号闭合再解析。
- **坏行只计数不断流**:第一行是表头时识别为表头;其余解析失败的行记进 `BadLines`,页脚写「N 行无法解析」。时间戳写坏的行里即便带「时间」两个字,也不会被误判成表头。
- **计数列不可信时回算**:`汉字个数` 缺失、为 0 或明显越界时,按明文真实码点数补上,而不是把 0 写进统计。
- **最近上屏是滚动窗口**:只保留最新的若干条并按时间倒序。1.9.0 预览版曾经写成「最旧的 40 条 + 最新 1 条」,超过 40 行后时间线会错位,2.0 修掉了。

## 找不到文件时

不是错误,只是没开这个功能。页面会给整页引导:期望路径、需要什么格式、为什么单独做一页,外加一个「重新读取」按钮。输入法按约定追加 CSV 之后,不用重启面板,自动出现统计。

## 每日日报（第 8 页）

每天第一次打开面板时,自动把**昨天**收成一张卡片并落盘:一次一天,靠数据文件里的 `daily_report_v1=` 去重,重开面板不会重复写、也不会覆盖你手改过的文件。

- **顶栏**:日期 + 星期 + 状态、一句话摘要、四个核心数字(击键 / 点击 / 有效使用 / 上屏字数),各带与基准的涨跌。
- **时间分布**:24 小时柱状图 + 最忙时段 + 最长连续使用段。
- **应用**:使用时长 Top 5。同一个 exe 的多窗口会合并——否则「msedge.exe」能占满五名。
- **操作习惯**:组合键 Top 5、按键 Top 3、鼠标路程、峰值 APM。
- **字符内容**:字数/次数/均长、汉字-标点-字母数字构成条、高频字、最长连续输入。
- **值得注意**:由具体数字触发的提醒,允许揶揄(「今天手有点懒？」「键盘替你喊累」),但每条都挂在某个字段上,不编造。

**对比基准是前 7 个「有数据」日的日均**,不是昨天:单日噪音太大,休假的日子也不该被算成退步。只有一天可比时表头写「前一天」,没有可比数据时写「无基准」——不会拿 0 当基准算出 +∞%。

页脚 **保存 Markdown** 写到 `%APPDATA%\键鼠统计\日报\yyyy-MM-dd.md`,**复制简报**进剪贴板;左右箭头翻前后一天(不能翻到未来),数字键 `8` 直达。

## 开机自动启动(默认关闭)

自启从「注册表 Run 键」换成「当前用户的计划任务」,**默认关闭**,由用户在托盘菜单里打开。

**为什么换。** Run 键写的是勾选那一刻的 exe 全路径。程序一旦被复制成别的文件名(比如为了对比版本而留下的 `KeyMouseStats-r7.exe` 这种副本),注册表不会跟着变,下次登录拉起的就是另一个文件;如果那个文件已经在跑,两个实例还会抢单实例互斥量,先启动的赢、后启动的静默退出——用户只看到「自启没生效」。

**现在怎么做。** 创建一个名为 `KeyMouseStats` 的计划任务:

- 触发器挂「开机」与「登录后」两路,并打开 `StartWhenAvailable`。开机那一刻还没有交互会话(窗口在 session 0 里显示不出来,低层键鼠钩子也收不到输入),任务会被排到用户登录的瞬间执行。对这类必须跑在交互会话里的程序,这是「开机就启动」在 Windows 上真正能落地的形态。
- 交互身份、普通权限:不弹 UAC、不需要管理员。
- 每次启动调用一次同步:任务登记的路径与当前 exe 不一致就重注册;历史遗留的 `KeyMouseStatsWidget` Run 项顺手清掉。**以后换文件名/挪目录,自启会自己跟上。**
- 开关状态直接来自任务是否存在,不再读注册表。开启成功会弹一条托盘气泡确认,失败会把真实原因(剥到最内层的 HRESULT 消息)弹出来——静默失败的自启比没有更糟。
- 同步在后台线程执行,不占用装了钩子的 UI 线程。

**升级影响。** 1.8.x 里勾过自启的用户,首次运行 2.0 时会把旧的 Run 项迁移成计划任务(保持「开启」意图);没勾过的保持关闭,不会凭空多出任何开机项。

## 回归

新增两个用例:

- `tests/RimeLogTests.cs`(**155 项检查**):码点与代理对、CSV 引号/转义/短行、跨行记录、未加引号的逗号、日志行解析与计数回算、区间聚合(字数/次数/小时/词长/构成/每分钟峰值/连续输入段/最近排序)、空区间、每日序列补零、导出往返、缺文件、坏行与空文件、刷新间隔设置。
- `tests/AutoStartTests.cs`(**15 项检查**):任务名与旧注册表值名的契约、路径归一化、同一文件判定(含大小写与引号)、查询接口不抛异常。

`build.bat` / `build-clean.bat` / `test.bat` 三处源文件清单同步。

## 升级

直接覆盖 `KeyMouseStats.exe`。键鼠数据格式仍为 v11,**没有改动任何键鼠落盘字段**,只多了一行可选的 `text_refresh_v1`;字符内容页是纯读取,不产生新数据文件。

自启换成计划任务后,旧的注册表 Run 项会在首次启动时自动迁移并删除——不用手动清理。
