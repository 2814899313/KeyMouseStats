# KeyMouseStats 2.3.5

2.3.5 修复 Rime `commit_log.csv` 带扩展列时的解析问题，并补齐可用于码效分析的衍生字段。

## 解析修复

新版日志格式：

```csv
时间点,字符数,明文,程序,方案,码长,候选序
2026-11-13 00:10:45,5,你现在看看,msedge.exe,rime_ice,15,
```

以前解析器把第 4 列之后都当明文的一部分，导致明文变成 `你现在看看,msedge.exe,rime_ice,15,`。现在按右侧元数据列锚定，明文、程序、方案、码长分别保存。

- 旧格式尾部空列不会污染明文。
- 候选序空值作为未知处理，不再冒充首选 `0`；显式 `-1` 表示非候选上屏。
- 总字符数按码点计算，汉字数只统计 CJK。
- 输入类型区分：`normal`、`raw_ascii`、`punct`、`mixed`、`other`。

## CSV 导出

导出升级为十列，明文、程序、方案按 RFC 4180 规则引号包裹，内部引号双写；逗号和换行不会撕裂列结构。

```text
时间点,字符数,明文,程序,方案,码长,候选序,总字符数,汉字数,输入类型
```

## 说明

KMS 仍然只**读取** Rime 写出的文件；扩展字段由 KMS 在读取和导出时计算，不会改写输入的 `commit_log.csv`。如果源日志希望直接记录首选下标，需要同步修改 Rime 侧写入插件。
