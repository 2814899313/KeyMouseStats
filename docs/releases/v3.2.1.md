# KeyMouseStats 3.2.1

修复实时事件库的 Unix 时间基准错误，并自动抢救已写入 3995 年的历史事件。

## 时间基准

- 新增 `UnixTime`：统一以 1970-01-01T00:00:00Z 为 Unix 毫秒基准，提供 `NowMs()` 与 `ToUnixMs()`。
- 修复 5 处误用“公元 1 年起算毫秒”的位置：
  - `DbWriter.EventClock._anchorMs`
  - `DbWriter.NowMs()`
  - `KmsDb.MergeKmsPackage` 的 `imported_ms`
  - `KmsSchema.Ensure` 的 `db_created_ms`
  - `V2Migrator.NowMs()`
- 实时会话与输入突发段的 `day` / `start_ts_ms` / `end_ts_ms` 恢复正常，与 `FlowBoard` 的 Unix 毫秒查询重新对齐。

## 3995 年历史事件抢救

- 数据库打开/Schema 检查阶段检测异常记录：`day >= '3900-01-01'` 或 `start_ts_ms >= 60000000000000`。
- 迁移前自动备份：
  - `kmstats.db` → `kmstats.db.bak-3995-fix`
  - `kmstats.db-wal` → `kmstats.db-wal.bak-3995-fix`
  - `kmstats.db-shm` → `kmstats.db-shm.bak-3995-fix`
  - 备份已存在时跳过，绝不覆盖第一次备份。
- 单个 SQLite 事务内：
  - 所有异常 `start_ts_ms` / `end_ts_ms` 减去 `62,135,596,800,000 ms`；
  - 按本地时区重算 `events_window_session.day` 与 `events_input_burst.day`；
  - 修正 `meta`、导入日志、窗口聚合中的异常时间戳；
  - 清理 `daily_summary` 等日聚合表中 `day >= '3900-01-01'` 的脏行；
  - 保留文本存档迁移进来的正确 `2026-*` 汇总，避免重复计数。
- 写入 `meta.epoch_fix_v1 = 1`；迁移失败自动回滚且不写标记，下次启动可重试。

## 洞察提示

- `DrawFlowCapsule` 接收具体提示字符串，不再硬编码「清爽版」。
- 三种状态明确区分：
  - 真正未启用事件库：清爽版显示原降级文案；
  - 标准版初始化失败：「事件数据库未就绪，请检查运行日志」；
  - 引擎正常但当天无数据：「当日暂无可分析的事件流，继续使用后将自动生成分钟级轨迹」。
