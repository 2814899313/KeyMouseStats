# KeyMouseStats 2.0.7

这一版有四件事:趋势页修掉「今天还没结束」造成的断崖,应用统计加入 APM 交叉分析,新增点击热区,并把所有美术主题补齐到九页。

## 八套美术主题完整覆盖九页

- 奥日、无限暖暖、士官长、生化危机、我的世界、小丑牌、大侠立志传和欧洲卡车均补齐「字符内容 / 日报 / 点击热区」专属背景,新页面不再显示纯色底。
- 新增 22 张 1672×941 高清主题素材。每张按页面语义单独构图,保留数据区留白,并通过等比覆盖裁切适配窗口,不拉伸人物与场景。

- 点击热区顶栏使用每套主题自己的题签,例如 `TACTICAL / HEAT`、`INCIDENT / HEAT`、`REDSTONE / HEAT`、`ROUTE / HEAT` 和 `SPIRIT / HEAT`。

## 按键排行:两级控制

- 一级主视图固定为「按键排行 / 组合键排行 / 全键热力图」,不再把时间、按住时长、单键/组合/热力平铺在同一层。

- 键盘热力卡片内重复的「击键次数 / 按住时长」开关已删除,只保留配列选择,同一个口径不再出现两次。

- 新增 `tests/KeysRender` 预览(排行/按住时长/组合键/热力两种口径/150%)。

## 趋势页:今日进行中不再制造断崖

- 早上打开趋势页,今天只有半天数据,原来会画出右端直接砸向谷底的折线、底部显示「较昨日 -95%」。现在:
- **最后一段折线改成虚线**,面积与平均线只铺完整日,末端标签写「今日截至 HH:mm · 累计中」;悬停今天的数据点显示「进行中」。
- **「较昨日」改成「较昨日同期」**:两边都只取已完成的整小时(09:57 打开比较的是 00:00–09:00),并在卡片小字写明比较窗口与昨日同期基数。
- **「日均」改成「日均·完整日」**,分母不再包含进行中的今天。
- 刚过零点没有完整小时时显示「累计中」,不硬算;滚轮与鼠标路程没有逐小时数据,同样显示「累计中」而不是估算一个百分比。
- **未运行的日子不再贴底画 0 直线**:没有落盘记录的日子画淡灰竖带并标「未运行」,折线断开、面积不填;日均和平均线只算有记录的完整日。悬停会说明「应用或电脑没有运行」。当天有记录但没打字仍是 0 点,悬停写明「这天有记录，但没有击键」。
- **面积渐变**:折线下方的蒙版按有记录的连续段填充,约 15% → 0% 渐变,不遮挡参考网格。
- **Y 轴整值刻度**:步长按 1 / 1.5 / 2 / 2.5 / 3 / 4 / 5 / 6 / 8 / 10 × 10ⁿ 对齐,原来 3.61k / 7.22k / 10.83k / 14.44k 现在是 4k / 8k / 12k / 16k;x 轴日期从最后一天往回取自适应步长,今天一定有标签。
- **按小时的活跃时长轴固定 0–60 分钟**:刻度 0 / 15 / 30 / 45 / 60,顶部参考线加粗;个别历史数据的 >60 分钟不会把刻度顶到 70。其他小时指标改用整值刻度(速率允许小数)。
- **小时速率统一为每分钟**:「击键/秒」改为 **击键/分(KPM)**,与「点击/分」同一时间基准;标题、卡片、悬停与导出 CSV 的单位一致,不再需要心算换算。
- 新增 `tests/AxisScaleTests`(76 项)与扩展后的 `tests/TrendCutoffTests`(19 项)、`tests/TrendRender`(未运行区间/有记录无击键/30 天空白/小时活跃 0–60/击键每分/悬停)。

## 修复:个别系统上「开机自启」报 DISP_E_UNKNOWNNAME

- 这是计划任务 COM 迟绑定按名字找不到成员(`IDispatch` 的 `DISP_E_UNKNOWNNAME`),常见于精简系统、任务计划 COM 注册异常或接口版本差异;不是权限不足,也不是服务没启动。
- 现在可选属性逐项 best-effort,单个属性名失败不再中止;失败会记录具体步骤到 `diagnostics.log`;COM 整体失败时自动退回 `schtasks.exe /SC ONLOGON` 创建登录触发任务,查询与关闭也有命令行兜底。

## 应用统计:APM 交叉分析与时长占比

- 应用页多了三种视角:**次数**(原列表)、**APM 效率**、**时长占比**。
- **APM 效率**:每个应用的「击键 + 点击 ÷ 前台活跃分钟」,按高低排序;VS Code、浏览器、Steam 可以横向比较。
- **全局 APM** 用「全部输入 ÷ 全部活跃时长」的加权口径,不是各应用 APM 的平均;只统计活跃 ≥60 秒的应用,过短样本单独计数。
- 悬停行给出击键/点击拆分、活跃时长、APM 与输入占比;「按窗口」粒度下,同一个 exe 的不同窗口各算各的。
- **时长占比**:前 6 个应用 + 「其他 N 个」的环图,中心是总活跃时长;右侧图例同时给出时长、占比和 APM,把「花时间多」和「输入密集」放在一起看。
- 「对比」摘要增加两个应用的 APM;导出 CSV 跟随当前视角(窗口明细附带 APM 列 / APM 排名 / 时长份额)。
- 顶栏按性质分组:时间范围、按应用/按窗口、带箭头的「今日分析 ↗」;「只看待标注」移到表格右上角并带数量,「键位构成」移进「次数」视图表头。
- 行首复选框替代每行「对比」按钮;每行加入原生 exe 图标,名称下只显示文件名,完整路径放到悬停提示。
- 顶部分类卡片可点击筛选;微信/QQ/钉钉/飞书等即时通讯统一归入「办公(沟通)」。
- 时长占比环图悬停时,中心显示所选应用的名称与精确时长。

## 新页面:点击热区

- **三档区间**:今日 / 近 7 天 / 近 30 天,都含今天,和按键排行页一致。
- **屏幕画布**:按当前显示器布局等比绘制每块屏幕,热力色只画在屏幕范围内;换过显示器布局后,落在画面外的旧点击只提示次数,不会画错位置。
- **屏幕九宫格**:左上、上中、右上、左中、正中、右中、左下、下中、右下。九宫格跟着**当前选中的屏幕**走,标题栏的「屏幕 N · 宽×高 ▾」可以换屏。
- **全部屏幕 / 单屏放大**:大桌面(或超宽屏、多屏)先看全局,再切单屏放大看具体格位;所选屏幕同时决定九宫格口径。
- **悬停明细**:屏幕编号、区域、次数、屏幕坐标、占比;也可以用 `Ctrl+C` 复制。
- **导出 CSV**:屏幕编号、屏幕 X、屏幕 Y、次数、占比,带区间、采样格和每块显示器布局的注释行。
- **空状态**:这一版开始积累,用一会儿鼠标就会出现;没有数据时页面不会误报「最热区域」。

## 多显示器与混合 DPI

- 程序 manifest 声明 **PerMonitorV2**,钩子与 `GetCursorPos` 拿到的都是物理像素,不会被 DPI 虚拟化。150% 主屏 + 4K 副屏混用时,两条采集通路仍会落到同一个格子。
- 显示器的大小、分辨率、横竖屏、排列方式都只是不同的矩形:画布按像素比例绘制,不把两块屏强行拉成一样大。
- 混合 DPI 布局可能留下**屏与屏之间的物理空隙**(例如 2560 宽的屏与起始于 3840 的 4K 屏之间空 1280 像素)。空隙不属于任何屏幕,不画格子;旧数据若落进空隙,单独记成「屏幕间空隙 N 次」。
- 九宫格只统计所选屏幕,其他屏幕的次数单独列在右下角,不再用主屏一份九宫格代表所有屏。
- 已知限制:32 像素是物理像素,4K 屏上的格子比 1080p 更细;画布按像素而非物理英寸;换主屏/换显示器位置后旧位置按当时的绝对桌面坐标保留,不重映射(需要后续版本记录显示器身份)。

## 采集口径与隐私

- 只多记一件事:**一次点击落在哪个 32 像素格**。不截屏,不记录窗口内容,不记录点击到了什么控件。
- 位置优先取低级鼠标钩子的精确屏幕坐标;原始输入(WM_INPUT)的点击包没有绝对坐标,用同一时刻的 `GetCursorPos` 补。两条通路看到的是同一次物理按下,用 30 ms 窗口去重——远小于人手双击间隔,不会把两次真实单击并成一次。
- **没有新增钩子**,键鼠计数与钩子看门狗的逻辑不变。
- 坐标按**虚拟屏幕**记录,主屏左边的副屏(负坐标)也能正确落格。
- 位置明细只保留最近 **30 天**;超过的日期只清采样格,当天的总点击数仍按「保留天数」保留。单日采样格上限 4000,导入异常文件不会把内存撑爆。

## 数据格式 v12

- 每个日期分节新增一行 `ch=格子X:格子Y:次数,…`,格子坐标 = 屏幕坐标 ÷ 32 向下取整;按 key 排序,文件内容稳定。
- `format=12`。旧版文件(v11 及更早)没有 `ch=` 行,照常读取,这一页显示空状态。
- 用旧版程序打开 v12 文件只会提示「文件来自更新版本」,其余数据照常;点击热区被忽略。
- 导入合并沿用 `DayRecord.AddFrom`:同一格子的次数相加,不覆盖。
- 按本机目前的点击量估算,30 天位置明细约占 200–400 KB;保存、备份轮转与导入合并都走原来的路径。
