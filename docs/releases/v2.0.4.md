# KeyMouseStats 2.0.4

这一版把「鼠标点击/滚轮偶发停止统计」从**结构上**解决了:不再让计数依赖那个会被 Windows 静默摘掉的低级钩子。

## 问题回顾

2.0.3 的做法是「被摘了就自己装回来」。它能保证不用重启,但本质是止血——只要回调偶尔超时,系统就会摘钩,中间那段时间的点击确实丢了。

而超时这件事**没法通过优化彻底消除**:低级钩子是全局回调,`LowLevelHooksTimeout` 默认 300 ms,回调里只要遇到一次跨进程卡顿(目标窗口无响应),系统就静默摘钩。把回调缩短到极致也只是降低概率。

## 这一版的思路:换一条没有超时约束的通道

鼠标的点击与滚轮有一条更稳的来源 —— **Raw Input**。注册一次(`RIDEV_INPUTSINK`,后台/焦点在别处都能收),之后由系统把数据包投递到我们的窗口过程:

- **没有 300 ms 的死刑线**。线程忙的时候包只会排队,不会丢。
- 不依赖钩子是否还活着。

所以 2.0.4 把这两项彻底搬到 Raw Input 上:

| 数据 | 来源 |
|---|---|
| 左键 / 右键 / 中键 / 侧键 | Raw Input(`RAWMOUSE.usButtonFlags`) |
| 滚轮 / 横滚 | Raw Input(`RI_MOUSE_WHEEL` / `RI_MOUSE_HWHEEL`) |
| 鼠标路程、光标路程 | 原有路径,未改动 |
| 键盘计数 / 组合键 / 按住时长 | 低级键盘钩子(时序更准,保留) |

如果原始输入注册失败(极少数环境),程序会**自动回退**到钩子计数——两条路径互斥,同一时刻只有一条在记数,不会重复计数。

## 键盘:保留钩子 + 1.5 秒探针

键盘没换源,因为按住时长和组合键依赖回调时序,原始输入经过消息队列会有几十毫秒抖动。取而代之的是给键盘加一个**探针**:

> 原始输入看到按键,而低级钩子 1.5 秒内没有任何事件 → 判定被摘 → 立即重装。

比 2.0.3 的 30 秒看门狗快一个数量级,最坏情况只丢 1.5 秒内的按键,且不需要重启。

## 组合起来

- **鼠标**:任何情况下都不会停。钩子被安全软件摘了也不影响点击和滚轮。
- **键盘**:极端情况最多丢 1.5 秒,自动接上。
- **兜底**:2.0.3 的 5 秒看门狗保留,覆盖「原始输入也没注册上」的环境。

## 回归

新增 `tests/RawInputTests.cs`(**33 项**):鼠标包按钮位(左/右/中/侧键 4/5)、滚轮正负增量、键盘包虚拟键与按放标志、鼠标包与键盘包互不误判、非法指针宽度与截断包一律拒绝。

原有的 `HookWatchdogTests`(13 项)继续覆盖看门狗判定表;`RimeLogTests` 159 项、`DailyReportTests` 13 项、`AutoStartTests` 15 项保持通过。

## 字符内容统计的启用条件

「字符内容」页依赖输入法自己写的上屏日志 `%APPDATA%\Rime\commit_log.csv`，因此**只在以下条件同时满足时可用**：

1. 使用 Windows 版**小狼毫输入法（Weasel）**；
2. 输入方案为**雾凇拼音**（rime-ice）；
3. 安装并启用配套的 **commit_log 插件**（把每次上屏写入上述 CSV）。

缺少任一条件时，页面会显示「未找到 commit_log.csv」，其余统计不受影响；微软拼音、搜狗、QQ 拼音等其他输入法不支持。程序只读取该文件，不挂钩子、不读剪贴板、不写入，字符数据不进入 `stats.txt`，也不参与导入合并与键鼠导出。

## 升级

直接覆盖 exe,数据格式不变。升级后如果鼠标仍然「点了不计数」,那基本只剩两种可能:原始输入注册失败且钩子也装不上(看 `diagnostics.log` 里的「钩子自愈:…重装失败」),或者安全软件把这程序整体拦了。
