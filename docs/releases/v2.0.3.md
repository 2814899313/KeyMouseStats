# KeyMouseStats 2.0.3

修一个「抽风」问题:**有时候鼠标点击、滚轮突然不再统计,键盘偶尔也中,必须重启程序才好**。

## 原因

低级键鼠钩子(`WH_MOUSE_LL` / `WH_KEYBOARD_LL`)是 Windows 的全局回调,**必须在 `LowLevelHooksTimeout` 内返回**(默认 300 ms),否则系统**静默摘钩**:不报错、不弹窗,小组件照常刷新,数字却永久停住。安全软件也可能主动卸钩。

而这个回调里原来做了一件不该做的事:每次点击都调 `AppActivity.Record(..., ForegroundApp.Capture(), ...)`,其中 `GetWindowText` 是**跨进程同步调用**——目标程序卡住时能阻塞几百毫秒(浏览器标签开太多、Office 弹模态框、资源管理器扫大目录都会)。连续点击时最容易踩线,这正好解释「点击和滚轮先出事」;键盘回调在「首次按下」时走同一条路径,所以偶尔也中。

次要触发点是解锁、休眠唤醒、会话切换之后钩子处于半失效状态。

## 修法

**1. 把跨进程调用赶出回调。** 窗口标题按「窗口 + 1 秒」缓存,同一窗口一秒内只取一次;进程路径沿用原来的 2 秒缓存。连续点击时每次回调的开销降到接近零。

**2. 看门狗,每 5 秒体检。** 两种信号触发幂等重装(先 `Unhook` 再 `SetWindowsHookEx`):

- 两个钩子句柄任一为 0(被安全软件或系统卸掉);
- 句柄都在,但**系统一直在收输入、我们 30 秒没记到任何事件**。

第二个信号用 `GetLastInputInfo` 算出系统空闲时间来区分「用户没动」和「用户在动但我们瞎了」。锁屏 / 休眠 / 会话断开期间不判停摆——那时钩子本来就收不到输入,重装只会打断仍按着的键。

**3. 解锁与唤醒后主动重装一次**(幂等,代价两次系统调用)。

**4. 不再静默。** 每次自愈写一行到 `%LOCALAPPDATA%\KeyMouseStats\diagnostics.log`:

```
2026-10-29T17:52:10.1234567+08:00 钩子自愈:计数停滞 30 秒(系统仍在收输入) → 已重装
```

只有**连续 3 次重装失败**才弹一次托盘提示,不会每 5 秒骚扰。

## 回归

新增 `tests/HookWatchdogTests.cs`(**13 项**):忙碌会话不重装、句柄丢失立即重装、用户空闲不误判、系统有输入但无计数才判停摆、读不到空闲时间不做判断,以及三个阈值本身(5 秒检查 / 30 秒停滞 / 10 秒空闲)。

## 升级

直接覆盖 exe,数据格式不变。升级后如果还遇到「停止统计」,先看 `diagnostics.log` 里有没有「钩子自愈」记录:

- **有记录且已重装** —— 自愈生效了,数字会自己接上;
- **有记录但重装失败** —— 大概率是安全软件拦着,把程序加入白名单;
- **完全没有记录** —— 说明不是钩子的问题,把日志发来再查。
