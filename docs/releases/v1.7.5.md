# KeyMouseStats 1.7.5

这一版只修一件事：**按键时长在「抬起丢了」之后会记账记错**。

## 丢失抬起不再变成一次假的长按

键盘钩子收不到抬起是常态：Alt+Tab 会被系统吞掉 Tab 的抬起，Win 键、提权进程（任务管理器、反作弊游戏）和全屏游戏吞键也会，锁屏与休眠期间干脆一个事件都收不到。

在此之前，这个键在我们眼里会一直「按着」，后果有两个：

- 这期间的**下一次敲击完全不被计数**（击键数、逐键计数、组合键、应用归因一起漏掉）；
- 而它之后的那次抬起，会跟**几分钟前**那次按下配对。于是两次敲击之间的间隔被记成一次 2—5 秒甚至更长的「按住」，插进直方图的最后两档，把该键的平均时长抬高，并让面板与报告里的「最长一次」基本等于「丢抬起的时间间隔」，而不是真实长按。

现在：同一个物理键在「已经按住」的状态下再次收到按下时，如果间隔超过了系统自动重复的上界（首次重复延迟最长 1000 ms，之后最慢约 400 ms 一次，这里取 1200 ms），就判定为**抬起丢失后的重新按下**——旧样本按丢失抬起丢弃并计入丢弃数，这次按下按一次全新的击键重新计数与计时。系统自动重复（间隔远小于阈值）的行为完全不变，仍然是「不重置起点、不重复计数」。

判定放在 `ShortcutTracker`：只有它能看到每一次按下（包括自动重复），也正好是决定「这次按下算不算一次击键」的地方，所以击键数与时长样本从同一条判定出来，不会再出现「记了时长却没记击键」。

## 锁屏 / 休眠 / 会话断开 / 替换数据时丢弃还按着的键

- `WM_WTSSESSION_CHANGE`（锁屏、会话断开）与 `WM_POWERBROADCAST`（休眠）现在会丢弃所有未抬起的按键并计入丢弃数。此前这两条路径只重置活跃度统计，按住时长的 pending 会一直挂着，回来后敲同一个键同样会错配。
- 导入时选择「整体替换」也会先丢弃未抬起的按键：替换会丢掉旧的日记录对象，否则那次抬起会结算到一条已经脱离 History 的记录上，样本既不落盘也不计丢弃。

## 时长取时点提前

按下侧的单调时钟此前是在抓取前台应用、更新逐键计数与热力图**之后**才取的。前台应用抓取里有跨进程 `GetWindowText`，目标窗口卡死时会阻塞几十到几百毫秒——这会把每一次按住时长都系统性地算短。现在按下时刻在钩子分支的最开头就取，这些工作全部发生在取时之后。

## 数据自洽与校验

- `hold_v1` 的加载改成与逐键明细、`AddFrom` 一致的累加语义。此前汇总是覆盖、明细是累加：同一天区段重复出现时（手工合并、拼接过的文件），分档合计会与逐键合计对不上。
- 逐日校验新增按住时长维度：分档之和、逐键样本之和必须等于样本数，均值必须落在 0—60 秒且不大于最长一次。此前这四个不变量完全没有检查。

## 升级

直接覆盖 `KeyMouseStats.exe` 即可，数据格式仍为 v11，1.7.4 的数据文件原样可用。1.7.5 之前记录的错配样本无法追溯修正——它们的时长恰好是两次敲击之间的间隔，没有留下可供还原的信息。
