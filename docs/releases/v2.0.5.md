# KeyMouseStats 2.0.5

这一版没有新功能,改的都是「数字看起来对、其实是错的」的地方。三处:一处区间交接、一处崩溃、一处口径。

## 趋势页「在报告中查看」现在带着筛选区间过去

趋势页上选「近 30 天」,点页脚「在报告中查看」,报告原来只会打开今天一天。

原因在 `Dashboard.CurrentRange` 的 `case TabId.Trend`:报告的终点固定为今天,起点也被写成今天,于是交给报告的是一天区间;而趋势页自己画的是 `Analysis.RangeDays(_trendRange)` —— 含今天、共 14 或 30 天。两边口径不一致。

现在起点按同一个公式算:

```csharp
else start = DateTime.Today.AddDays(-(_trendRange - 1));
```

选 14 天带过去是 14 天,选 30 天是 30 天,与面板完全对齐。按小时的单日分支没有改动。

顺带一提:报告第 2 页「每日趋势」的柱图仍是固定的 30 天窗口(它只读所选日期,不读区间)。这是既有的设计,不在这一版里改。

## 开启「每日目标」后,空区间会让报告直接打不开

从总览页点「在报告中查看」时,面板交出的区间是「今天—今天」。区间口径会把终点收回到最近一个完整日(昨天),于是 `to < from`、聚合结果里没有任何完整日,`RangeMetrics.Days = 0`,而它的 `Start/End` 还是结构体默认值 `0001-01-01`。

「区间回顾」页渲染「目标达成天数」时,只对**上期**检查了 `Days > 0`,本期没有。于是 `0001-01-01` 被当成真实日期区间传进 `Wellbeing.GoalStats`,循环第一次迭代就要往前减一天,`DateTime.AddDays(-1)` 越界抛 `ArgumentOutOfRangeException` —— 报告窗口在构造期间就崩了。

修法两层:

1. **消费端**:本期也补上 `Days > 0` 判断,与上期同一口径;空区间直接记 0 / 0 天,不把默认值传下去。
2. **兜底**:`GoalStats` 自己拒绝 `DateTime.MinValue` 这类「未设置」的边界值,任何调用方传进来都不再可能越界。

这条只在设置了每日目标(`GoalEnabled`)时出现 —— 目标默认关闭,所以平时测不到。

## 字符内容:「平均每次字数」不再把标点算进去

中文输入法里「，」「。」通常单独提交一次。它们既计入上屏字数、又计入上屏次数,把「平均每次字数」系统性拉低:单独敲一个逗号,等于「1 次上屏 / 1 个字」。

这一版给这个指标单独一套口径:

- **标点不算字**:一次上屏只统计非标点码点(符号类也按标点处理,与「字符构成」的分类一致);
- **只上屏标点的那一次不算次数**:分母是「含至少一个非标点字符的上屏次数」。

举个例子(虚构):

| 上屏 | 旧口径 | 新口径 |
|---|---|---|
| 「你好，」 | 1 次 / 3 字 | 1 次 / 2 字 |
| 「，」 | 1 次 / 1 字 | 不计入 |
| 「世界」 | 1 次 / 2 字 | 1 次 / 2 字 |
| 合计 | 3 次 / 6 字 = 2.00 | 2 次 / 4 字 = 2.00 |

上面这个小样本刚好凑成同一个平均值,真实数据里不会:本机实测 3 650 次上屏中有 371 次是纯标点上屏,平均每次字数 **2.92 → 3.13**。

范围**只有这一张卡**。卡片 1「区间上屏字数」、卡片 2「上屏次数」、每日与时段图、词长、输入节奏、页脚、日报仍是原口径(含标点) —— 它们是「上屏了什么」的原始视图,不参与这个平均值。卡片 3 的副标题改为「字 / 次 · 不含标点」,避免读者拿它和左边两张卡直接相除。区间内只有标点时显示 `--`,不显示 0.00。
